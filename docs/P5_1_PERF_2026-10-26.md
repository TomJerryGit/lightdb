# P5.1 性能深化记录（2026-10-26，beta.77）

环境：本机 Windows，LightDB 4.0.0，10k 行 / 100 个不同值（`region`）测试集。

## 1. WAL 命名多段轮转

- 活动段仍 `<table>.wal`；超过段大小后归档为 `<table>-wal-000001.log` 并开新活动段，LSN 跨段单调
- 段大小：`LIGHTDB_WAL_SEGMENT_BYTES` / `Table.wal_segment_bytes`（默认 256KB）
- checkpoint 保留最近 K 段：`LIGHTDB_WAL_KEEP_SEGMENTS` / `Table.wal_keep_segments`（默认 0 = 旧语义清空）
- 启动按段序重放（归档序号 + 活动段），跨段崩溃恢复 / loser undo 测试通过
- 量化：段 4KB、K=2 时单归档段 ≤4250B，checkpoint 后总量 5102B ≤ 理论界 `(K+1)*(段+记录余量) ≈ 24.6KB`

## 2. 单列非唯一二级索引真实加速

| 查询 | 无索引 | 有索引 | 加速 |
|---|---:|---:|---:|
| 点查 `region=42` | ~143 ms | ~3.5 ms | **~40×**（复测 26–35×） |
| 窄点查 `region=42 AND val=...` | ~141 ms | ~4.2 ms | ~33× |
| 范围 `BETWEEN 10 AND 12` | ~348 ms | ~25 ms | **~14×** |
| 范围 `>=98` | ~140 ms | ~13.8 ms | ~10–13× |
| `ORDER BY region LIMIT 20` | ~289 ms | ~1.3 ms | **~220×**（复测 ~300×） |

- 结果与全表扫描**逐行一致**；BETWEEN 下推为范围比较后走索引
- 写后标脏、查询时从 `_live_rows()` 懒重建；重启/崩溃/COMPACT 后一致
- 活跃事务/OR/LIKE/表达式/多列索引 → **安全回退全表扫描**（结果仍复核）
- `SHOW INDEX`：单列 `BTREE` + 真实 Cardinality；多列仍 `SCAN-ASSIST`（不谎称）

## 4. 剩余边界

- 多列二级索引仍只声明（SCAN-ASSIST），不加速
- 索引映射懒重建：写后首查 O(N)（基准为热态）
- 仅单列索引与简单字面量 BETWEEN 下推，复杂表达式回退全表扫描
- WAL 仅活动段保留旧文件名 `<table>.wal`，归档段带表前缀 `<table>-wal-NNNNNN.log`
