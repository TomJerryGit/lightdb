# 迁移：旧 B+Tree 页格式（v1/v2/v3）→ v4

**背景**：task-72 为支持 2 列复合主键把键扩到 `uint64`（v2，叶/内部条目
16/12B）；task-80 支持 3–4 列复合主键（v3，24/20B、128 位键）；task-92
支持 **5–8 列复合主键**，键最大 256 位，页格式升级为 **v4**：叶子条目
**40B**（32B 大端键 + pid/sid）、内部条目 **36B**（32B 大端键 + child）。
v1（12/8B）、v2（16/12B）、v3（24/20B）数据文件**不能**被 v4 直接读取：
新版本启动时会检测 `.btroot` 根页，发现不是 v4 格式后**显式拒绝启动**
（不会按 v4 误读旧页、静默返回错行/损坏索引）。

错误示例：

```
LegacyBTreeFormatError: 检测到旧版 B+Tree 页格式（v1/v2/v3）：表 'users'
的根页 2（.../users.dat）不是 v4 格式（32 字节大端 256 位键）。...
请先备份数据目录，然后运行：
`python scripts/migrate_btree_format.py <旧数据目录> <新数据目录>` ...
```

## 迁移步骤（务必先备份）

1. **停止服务/关闭数据库进程**：迁移要求旧库是**正常关闭/checkpoint**
   后的状态。若上次是崩溃退出（`_meta.json` 有 `pending_ddl` 或仍有未重放
   WAL），请先从备份恢复旧目录，再重新正常启动一次旧版本完成 checkpoint，
   或直接用完整备份做逻辑恢复。
2. **备份旧数据目录**（复制整个目录，不要只复制 `.dat`）：
   ```powershell
   Copy-Item -Recurse data data_backup_pre_v4
   ```
3. **运行迁移脚本（旧目录只读，必须写到新目录）**：
   ```powershell
   python scripts\migrate_btree_format.py data data_v4
   # 目标目录已存在且非空时，确认备份后加 --force
   python scripts\migrate_btree_format.py data data_v4 --force
   ```
   脚本逐表：
   - 扫描旧堆页读取 `xmax=0` 的可见行（正常关闭后的当前数据）；
   - 用当前 v4 格式重建表：列定义、PRIMARY（1–8 列复合）/UNIQUE/二级索引、
     CHECK、分区、表选项、AUTO_INCREMENT 计数；
   - 逐行插入并校验行数与**行内容**（含 2–8 列复合主键的元组）；
   - 复制 `_meta.json` 中的用户/视图，以及 `_stored.json` / `_triggers.json`
     / `_events.json` / `root.password`（若存在）。
4. **用新目录启动服务**（配置里的数据目录指向 `data_v4`），抽查：
   - `SELECT COUNT(*)` 行数、主键点查/前缀/范围查询；
   - `SHOW CREATE TABLE` / `SHOW INDEX` / `SHOW COLUMNS`；
   - 写一条再删一条、重启后复验。
5. 确认无误后保留旧目录作为回滚备份；新版本**只**使用新目录。

## 迁移限制（脚本会显式报错，不会静默丢数据）

- 支持 v1、v2、v3 → v4；已是 v4 的目录无需迁移（脚本显式提示）。
- 旧格式最多 4 列复合主键；元数据若出现 >8 列主键说明被手工改过，脚本拒绝。
- 不迁移未完成/半提交的 WAL 重放状态；请先正常关闭旧库。
- 不迁移 binlog 文件（复制位点请重新初始化从库）；不迁移 `.free` 空闲页
  登记表（新库会重新生成）。
- 旧表 `.dat` 不存在（空表元数据）时按空表迁移；行载荷列数与元数据不一致
  会显式报错。
- 迁移是"读到新目录"的一次性操作，旧目录不被修改。

## 页容量影响（v4）

固定 32B 键使页条目变大：

| 版本 | 叶条目 | 内部条目 | 叶容量（近似） | 内部容量（近似） |
|---|---|---|---|---|
| v3 | 24B | 20B | 168 | 202 |
| v4 | 40B | 36B | 100 | 111 |

大表 B+Tree 高度可能增加 1 层；点查/前缀/范围仍为 `O(log n + k)`。

## 验证格式检测

直接启动新版本指向旧数据目录，会抛出
`lightdb.db.errors.LegacyBTreeFormatError`（含表名/根页/迁移脚本路径）。
v4 根页页头 `reserved[21]` = 4；v3=3、v2=2、v1=0。对无 marker 的历史库
会按条目结构（12/8、16/12、24/20、40/36 字节 + 槽位/子页有效性）判定，
避免误读。
