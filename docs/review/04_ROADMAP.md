# LightDB 优化路线图（基于 2026-10-13 全面评估）

依据：[00_SUMMARY.md](00_SUMMARY.md)、[01_engine.md](01_engine.md)、[02_studio.md](02_studio.md)、[03_integration_and_perf.md](03_integration_and_perf.md)、[../FAILURE_TRIAGE.md](../FAILURE_TRIAGE.md) §9

## 0. 指导原则（本会话验证有效的三条）

1. **绝不静默错答**：要么算对，要么显式报错。本会话已清掉十几处静默错答（别名 JOIN 被丢弃、`WHERE 列=列` 恒假、`IN` 多列截断、HAVING 被整段丢弃、投影标量子查询填 NULL、`ORDER BY a,b` 只按首列、策略 id 撞号覆盖……），**同样的标准必须用于 OLAP/列存/CHECK/GUI 错误展示**。
2. **证据优先于文档**：白皮书数字（12,000 QPS、3.5M rows/s、41x、12.5x）目前**在查询路径上没有落点**。任何性能声明必须绑定可复现命令与实测输出，做不到就摘牌。
3. **判据用三件套**：①改动领域零失败；②干净 HEAD `worktree` 对照无净新增失败；③关键能力的最小复现脚本。**不要用全量失败总数**（本会话实测它在 37–41 之间抖动）。

## 阶段 2：性能（1–2 周，按收益排序）

| # | 事项 | 证据 | 验收（可量化） |
|---|---|---|---|
| 2.1 | **checkpoint + WAL 轮转** | WAL ≈200 B/行且无 `checkpoint` 生产调用者；10 轮 UPDATE 使 `.dat` 669 KB→16 MB | 20 万次写入后 WAL ≤ 32 MB（阈值可配）；重启恢复时间 < 2s；崩溃恢复不回归 |
| 2.2 | **审计批量 flush + 可关** | 每条语句 `flush()` → 批量 INSERT 1,356 rows/s **慢于**逐行 1,501 rows/s | 批量 500 行/语句 ≥ 逐行的 **2 倍**；审计可异步/批量，默认不影响正确性 |
| 2.3 | **页内紧凑（vacuum 真回收）** | `vacuum()` 回收 0、文件不变；只有 `shutdown()` 才压缩 16 MB→1.7 MB | 在线 `vacuum()` 后 `.dat` 至少缩小 50%（有可回收版本时）；数据与历史快照仍正确 |
| 2.4 | **把查询从 GIL 里挪出去** | 8 客户端并发 1,163→749 q/s（−36%）；并行 `COUNT` 0.49x 负加速 | 1→8 客户端**吞吐不下降**（≥1.0x）；并行路径要么 ≥1.5x 要么屏蔽 |
| 2.5 | **点查/QPS 达标路径** | 888 q/s 进程内、1,138 q/s TCP；白皮书 12,000 QPS 差 13.5 倍 | 先定**可辩护的目标**（如单机 3,000 q/s）并写进基准门禁，达不到就改文档 |
| 2.6 | **OLAP 决策点** | 三层未接入 SQL 路径 | 二选一：接入（列存 + 向量化进计划，且 0.1/0.2 已修）或**摘牌并从代码库移除以降低误解** |

**阶段 2 出口标准**：写吞吐 ≥3,000 rows/s（批量 ≥6,000）；并发不下降；文件增长有硬上限；性能数字全部有 `benchmarks/` 脚本可复现。

## 阶段 4：定位与架构（4 周以上，需要决策）

1. **产品定位二选一**：① 定位"内部原型/教学项目"——那就**把宣传与 UI 入口裁剪到真实能力**（去掉 Navicat 类比、移除未实现功能的菜单）；② 定位"可用的管理工具"——则阶段 3.1 P1 + 3.2 全部为**入场券**（不能跳过）。
2. **多进程查询并行**：目前多进程只并行"连接/协议"，查询仍单线程。若要利用多核，需要在存储层做**只读副本/页共享**或**进程内分片**（后者已有雏形：`lightdb/parallel/table_view.py`）。
3. **复制体系补齐**：`Seconds_Behind_Master` 需要给 WAL 事件加时间戳；binlog 位点目前是事件序号而非字节偏移、日志名固定不轮转——**要么补齐、要么在文档里明确这是"内部事件流"语义**。
4. **Cython**：`.pyx` 已静态修好 6 处编译错误但**本机从未编译**；要么在有编译器的机器上编译并用 `status()['any_accelerated']` 验收，要么删除该层以免误导。

## 明确「不做」

- ❌ 让 `test_parallel_speedup` 在 `ThreadPoolExecutor` + GIL 下达标——**物理上不可能**，应改为多进程或删该断言。
- ❌ 追逐白皮书的 12,000 QPS / 3.5M rows/s / 41x，除非先完成 2.1/2.4/2.6 并重测。
- ❌ 在 OLAP/列存未接入 SQL 路径前，为其继续增加功能（如 0.1/0.2 未修则先修，不扩面）。
- ❌ 为"看起来完整"而保留未实现功能的 UI 入口（点击无反应比缺失更伤信任）。
